## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：`num_train_epochs` を 20 → 10 に変えた（ほかは同じ）。変えたあとセッションを再起動して上から実行した。
- 結果（比較表や数字）：

| | エポック20（元の設定） | エポック10 |
|---|---|---|
| ステップ数 | 40 | 20 |
| 学習時間 | 229 秒 | 115 秒 |
| Training Loss（10ステップ目） | 1.5606 | 1.5602 |
| Training Loss（20ステップ目） | 0.0842 | 0.0971（最終） |
| 最終 loss | 0.0141（40ステップ目） | 0.0971（20ステップ目） |
| 学習後 `format_rate` | 1.0 | 1.0 |
| 学習後 `content_rate` | 0.905 | 0.905 |
| 退行 | なし | なし |
| 知識質問の分類 | asserted / needs_review / needs_review / asserted | 同じ |

  エポックを半分にすると学習時間はほぼ半分になり、最終 loss はエポック20の約7倍だったが、形式遵守率と内容正解率は同じだった。違いが出たのは文面で、エポック10の「確認が必要」の答えは「この FAQ には記載がありません。**必ずに**確認が必要です。」となり、教師データの「**運営に**確認が必要です」を写しきれていなかった。

- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：出力の形式や決まった言い回しをそろえたいとき。今回は14件・数分の学習で、プロンプトで指示しても守れなかった JSON の形式が全問そろった。採点の指標（形式・内容）では、エポック10でもエポック20と差が出なかったので、形式を覚えさせるだけなら少ない学習で足りる。ただし loss や文面の細部には差が出たので、指標に入らない部分は出力を目で読んで確かめる必要がある。
  - 向かない場面：知らない事実について「分からない」と判断させたいときや、知識を正しく増やしたいとき。どちらのエポックでも、FAQ と言葉が近い質問に別の項目を当てはめて言い切る失敗が残った。根拠の有無が大事な用途では、学習だけに頼らず、根拠の文書を検索して渡す仕組みや、出力を確かめる仕組みと組み合わせるほうがよいと考えた。
